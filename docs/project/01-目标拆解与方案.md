# 目标拆解与技术方案

## 1. 目标拆解（WBS）

```
G0 可运行的《摸鱼锅》
├── G1 工程骨架（Vite + TS + 竖屏画布）
├── G2 关卡数据与生成（种类、数量、层级遮挡）
├── G3 渲染（锅、物块、槽、HUD）
├── G4 交互（点选、三消、失败、通关）
├── G5 颠锅（改遮挡 + 次数 + 广告加次）
├── G6 结算与文案、复活广告流
├── G7 双关流程（试锅 → 挑战）
└── G8 验收测试（手测脚本 + 自动冒烟）
```

## 2. 技术选型

| 项 | 选择 | 原因 |
|----|------|------|
| 运行时 | 浏览器 Canvas 2D | 零平台审核门槛，本环境可真跑 |
| 构建 | Vite + TypeScript | 启动快、易测 |
| 引擎 | 自研轻量状态机，不上Unity/Cocos | MVP体量小，避免环境依赖卡死 |
| 广告 | `AdService` 模拟激励视频（真实等待） | 无广告SDK时仍验证完整商业化流程 |
| 存储 | localStorage 记锅贴/当日进度 | 轻留存，可测 |

## 3. 相对原GDD的修正

| 原设计 | 修正 | 原因 |
|--------|------|------|
| 2个相同消除，槽位4 | **3个相同消除，槽位7** | 对齐羊/鹅市场验证手感 |
| 摇一摇必选 | 按钮为主，DeviceOrientation可选增强 | 桌面测试友好 |
| 12种物体全开 | MVP教学4种、挑战8种 | 控难度 |

## 4. 迭代原则

遇到卡点：先写进 `.learnings/ERRORS.md` → 必要时回查调研 → 改方案文档 → 改代码 → 再验收。  
禁止用“TODO占位按钮”冒充已完成的核心规则。
